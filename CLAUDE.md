# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal AUR package repository for Arch Linux. Three Arch machines share a single S3-hosted pacman repo (`[jantman]` at `http://archrepo.jasonantman.com/current/`). Only one machine — `phoenix` — builds packages; the other two install via `pacman -Syu` against the S3 repo. This repo holds the tooling that drives that workflow.

The repo itself does **not** track PKGBUILDs — `aurutils` keeps its own git clones (with full history) under `~/.cache/aurutils/sync/`. Old top-level `*/PKGBUILD` directories are historical snapshots that pre-date the aurutils migration; do not update them. `packages.list` is the only checked-in artifact that reflects current repo contents (regenerated by `update-package-list.sh`).

## Common commands

All shell scripts assume the repo is at `/home/jantman/GIT/arch-pkgbuilds/` on phoenix and that `[jantman]` is configured in `/etc/pacman.conf` with `Server = file:///home/jantman/GIT/arch-pkgbuilds/repo`.

```bash
# Add a new AUR package (interactive PKGBUILD diff review)
aur sync --database jantman <package-name>

# Check what needs updating without building
./aur-rebuild.sh --dry-run

# Build all AUR updates + library rebuilds (skips IGNORE_PACKAGES)
./aur-rebuild.sh

# Force-rebuild a specific package
./aur-rebuild.sh --force <package-name>

# Find/remove repo packages not installed on any machine
./aur-prune.sh                                # dry run, this machine only
./aur-prune.sh other1.txt other2.txt          # dry run with remote pacman -Q dumps
./aur-prune.sh --remove other1.txt other2.txt # actually remove

# After any of the above: publish to S3 and refresh packages.list
./update_sync.sh
./update-package-list.sh

# Check for packages linked against outdated libraries (also runs as part of aur-rebuild.sh)
checkrebuild -i jantman
```

`update_sync.sh` activates `~/venvs/current` for `arch_repo_index.py` and uses `~/bin/aws` — both paths are hardcoded.

## Architecture notes

- **`aur-rebuild.sh`** wraps `aur sync --upgrades` (AUR version updates) followed by a `checkrebuild`-driven loop that rebuilds packages whose linked libraries have changed. Library rebuilds use `aur sync --no-ver -f` so aurutils doesn't skip a same-version package — see commit `57b75c4`. `IGNORE_PACKAGES` at the top of the script lists packages that must be updated manually (kept in sync between the upgrade pass and the rebuild loop).
- **`aur-prune.sh`** uses `aur repo --list` as the source of truth for repo contents and matches package filenames in `repo/` with a regex anchored on `pkgname-pkgver-pkgrel-arch.pkg.tar.*` so it doesn't accidentally match packages with overlapping name prefixes.
- **`update_sync.sh`** regenerates `repo/index.html` via `arch_repo_index.py` (reads the repo's `.db.tar.gz` directly), then `aws s3 sync --delete` to `s3://archrepo.jasonantman.com/current/`. The `--delete` is intentional — old package versions removed by `repo-add`/`repo-remove` should disappear from S3 too. Note the script's caveat about `repo-add` doing lexicographic, not version-aware, comparison when multiple versions of the same package are in the source dir.
- **`arch_repo_index.py`** parses the pacman repo `.db.tar.gz` (a tar of `desc` files) to build an HTML index. Standalone Python script with `pytz`/`tzlocal` deps.
- **`repo/`** is gitignored and contains the actual `.pkg.tar.{zst,xz}` files plus `jantman.db.tar.gz`. Never commit it.
- **`rebuild.py`** and **`aurget.sh`** are legacy (pre-aurutils). Don't extend them; use the `aur-*.sh` scripts.

## Inter-package dependencies

A handful of packages in this repo depend on others in this repo. `aurutils` handles ordering automatically when these are built together, but be aware when force-rebuilding: rebuilding a base package may require rebuilding its dependents too. Known chains (from `github_actions_process.md`):

- `levmar` → `f2c`
- `libfprint-2-tod1-xps9300-bin` → `libfprint-tod`
- `perl-http-server-simple-authen` → `perl-authen-simple`
- `fusioninventory-agent` → `perl-http-server-simple-authen`, `perl-io-capture`, `perl-proc-daemon`, `perl-xml-treepp`, `perl-universal-require`

## Fleet workflow

Always build on phoenix first, run `pacman -Syu` on phoenix, and only update the other two machines a day or two later if nothing broke. Library-rebuild triggers (new glibc/openssl/python/etc.) are caught by `checkrebuild` after the system update, which is why `aur-rebuild.sh` runs it.
